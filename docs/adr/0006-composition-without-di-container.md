# Композиция серверного графа: явные фабрики, без DI-контейнера

Status: accepted

Серверный граф объектов собирается одной функцией `composeDependencies()` в
`server/composition.ts`; `buildApp()` остаётся HTTP-оболочкой и вызывает её. Сценарии
по-прежнему получают зависимости явными аргументами, роуты получают сгруппированные
возможности и не видят репозиториев. DI-контейнер рассмотрен и отвергнут по замерам, а не по
вкусу; слои и границы [ADR 0004](0004-server-layers.md) не меняются. Решение собрано по
итогам разбора «много кода в `server/app.ts`»
([#51](https://github.com/kitXIII/ai-for-developers-project-386/issues/51)).

## Решение

- `server/composition.ts` — композиционный корень: `composeDependencies({ now?, schedule? })`
  возвращает `{ schedule, meetingTypes: { list, get, create, listSlots }, bookings: { create,
  listUpcoming } }`. Это единственный экспорт модуля.
- `assertSchedule` вызывается здесь: конфигурацию читает тот, кто её собирает. Строковые часы
  `now: () => string` конвертируются в `nowMs` на этом же шве (ADR 0004, «Шов часов»).
- `buildApp` передаёт в каждый роут явный список зависимостей; типы опций объявляются локально
  в файлах роутов — импорт из `server/composition.ts` запрещён (`routes → server` отклоняется
  `easement`).
- Цена: `server/` +20 строк, `app.ts` 107 → 73. Выигрыш не в строках: `app.ts` перестаёт
  быть точкой роста, а `pg` получает место для пула и жизненного цикла.

## Considered options

- `@fastify/awilix` (живой преемник deprecated `fastify-awilix`) — отвергнуто. Дефолтный
  контейнер плагина — модульный синглтон: замерено, что два `buildApp` в одном процессе видят
  регистрации друг друга, а `app.close()` одного dispose'ит граф другого, что несовместимо с
  десятками приложений на прогон тестов. Сервисы `(deps, input)` требуют карри-обёрток, поэтому
  семь биндингов не исчезают, а переезжают; ключи не проверяются компилятором, `Cradle` —
  глобальный god-type. Только на регистрации и типы уходит ~25 строк — больше, чем весь объект
  композиции (~20 строк), не считая карри-обёрток.
- Единый бандл `AppDeps` в роутах (без замыканий) — отвергнуто: роуты структурно получают
  репозитории, и граница видна только по импортам, а не по типу.
- `app.decorate('deps', …)` — отвергнуто: роуты видят весь граф, `FastifyInstance`
  аугментируется глобально на процесс.
- Оставить всё в `app.ts` — отвергнуто: файл смешивает HTTP-каркас и граф, каждая новая
  зависимость приходит в него.

## Consequences

- Триггер пересмотра контейнера: (i) графу понадобится жизненный цикл или скоупы (пул,
  транзакции, состояние на запрос), (ii) сквозных зависимостей композиции станет больше 10,
  (iii) появится вторая точка сборки (воркер, CLI). Пока не выполнено ни одно.
- `pg` приходит в `composeDependencies()`; пул и `onClose` появятся там вместе с БД
  ([#52](https://github.com/kitXIII/ai-for-developers-project-386/issues/52)).
- Новых тестов нет: проводку держит контрактный тест, `assertSchedule` — по прецеденту 0004.
- Пересмотренное в 0004: композиционный корень (был `buildApp`) и место `assertSchedule`.
  Слои, порты и правило «сценарий перечисляет свои зависимости» остаются в силе.
