# Design First: контракт TypeSpec опережает реализацию

Status: accepted

Разработку фич ведём от контракта: сначала проектируем или правим API в TypeSpec
(`packages/api/spec/*.tsp`), затем генерируем артефакты (`pnpm gen` → OpenAPI + SDK/типы/Zod)
и только после этого реализуем сервер и клиент независимо друг от друга. Единый контракт —
источник правды, расхождения ловятся статически (tsc по сгенерированным типам), контрактным
тестом (`test/api/contract.test.ts`) и `gen:check` в CI. Альтернатива — code-first, когда сервер
и клиент пишутся без общего контракта, — ведёт к рассинхрону контракта и двух реализаций,
поэтому от неё отказались.
