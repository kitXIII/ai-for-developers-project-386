# Тест-план

Перечень проверок, которые должны существовать к моменту приёмки фичи (Design First, ADR 0001).
Фича считается принятой, когда каждая строка плана существует в репозитории как тест:
незаведённая проверка остаётся пустой строкой чек-листа и не удаляется.

Каждая строка помечена сценарием README:

- **С1** — сценарий владельца: создание типа встречи;
- **С2** — сценарий гостя (в README — «участника»): создание бронирования;
- **С3** — сценарий владельца: проверка бронирований;
- **—** — инфраструктурная проверка вне трёх сценариев.

Слои не дублируют друг друга: контракт — форма и поведение API по контракту; юнит — краевые
случаи доменных правил; e2e — пользовательские сценарии через UI; tsc — соответствие типов
сгенерированному SDK (без рантайм-проверок).

## Контракт (`test/api/contract.test.ts`)

Vitest + `app.inject`: живой сервер против JSON Schema из `packages/api/generated/openapi.json`
(ajv 2020). Двухуровневый: (а) генеральная проверка схемы — любой ответ любой операции против
задокументированного статуса, включая POST с телами; (б) именные сценарные тесты на семантику,
которую схема не выражает. Состояние сеется через API (создать тип → бронь), без прямых инъекций
в память сервера. Детерминизм: свободный слот берётся из ответа `GET /slots` (сервер сам называет
дату), а для веток «вне окна»/«вне расписания» «сегодня» заморожено.

- [ ] Генеральная: ответ каждой из 8 операций валиден против JSON Schema openapi.json
      (включая POST с телом и статусы 400/404/409). —
- [x] Создание типа встреч: 201, форма `AdminMeetingTypeCreated`. — С1
- [ ] Создание брони: 201; `end` вычислен сервером; `start` в ответе со смещением `+03:00`;
      `meetingTypeName` денормализован. — С2
- [ ] 400 `validation_failed`: `name`/`guestName` вне 1–100 символов или из одних пробелов;
      `durationMinutes` вне 5–540. — С1, С2
- [ ] 404 `meeting_type_not_found`: неизвестный id в получении типа, слотах и брони. — С2
- [ ] 409 `slot_taken`: повторная бронь занятого слота. — С2
- [ ] 409 `outside_window` / `outside_schedule`: старт вне окна записи или расписания. — С2

## Юнит (генератор слотов)

Vitest над чистой функцией генерации слотов (ADR 0002); «сегодня» заморожено.

- [x] Окно записи D+1…D+14 по UTC+3; сегодня всегда исключён. — С2
- [x] Будни 9:00–18:00 UTC+3; выходные входят в окно, но слотов не дают. — С2
- [x] Сетка стартов от 09:00 с шагом, равным длительности типа; хвост дня отброшен. — С2
- [x] Строгое непересечение с бронями любого типа; стык-в-стык разрешён. — С2
- [x] Границы длительности типа 5–540 минут. — С1

## Покрывается типами (тесты не пишем)

Ловится тремя проходами tsc и `gen:check` статически; типы ловят форму, не поведение —
бизнес-правила сюда не входят, для них есть слои выше.

- Соответствие сервера и клиента типам сгенерированного SDK по каждой операции.
- Zod-схемы форм из `@app/api/zod`.
- Типизация React Query (`@app/api/react-query`).

## Вне контракта

- [x] JSON-404 неизвестных маршрутов (`{ message: 'Not Found' }`, дефолт Fastify) — пинится
      существующим `test/server/app.test.ts`; контракт описывает только известные маршруты. —

## Гейты CI

`gen:check` (перегенерация + `git diff --exit-code` по `packages/api/generated`) и контрактный
тест входят в `mise run check`: расхождение артефактов с контрактом или сервера с контрактом
роняет проверку.
