# Тест-план

Перечень проверок, которые должны существовать к моменту приёмки фичи (Design First, ADR 0001).
Фича считается принятой, когда каждая строка плана существует в репозитории как тест:
незаведённая проверка остаётся пустой строкой чек-листа и не удаляется.

Каждая строка помечена сценарием README:

- **С1** — сценарий владельца: создание типа встречи;
- **С2** — сценарий гостя (в README — «участника»): создание бронирования;
- **С3** — сценарий владельца: проверка бронирований;
- **—** — инфраструктурная проверка вне трёх сценариев.

Слои не дублируют друг друга: контракт — форма и поведение API по контракту; юнит — краевые
случаи доменных правил; e2e — пользовательские сценарии через UI; tsc — соответствие типов
сгенерированному SDK (без рантайм-проверок).

## Контракт (`test/api/contract.test.ts`)

Vitest + `app.inject`: живой сервер против JSON Schema из `packages/api/generated/openapi.json`
(ajv 2020). Двухуровневый: (а) генеральная проверка схемы — любой ответ любой операции против
задокументированного статуса, включая POST с телами; (б) именные сценарные тесты на семантику,
которую схема не выражает. Состояние сеется через API (создать тип → бронь), без прямых инъекций
в память сервера. Детерминизм: свободный слот берётся из ответа `GET /slots` (сервер сам называет
дату), а для веток «вне окна»/«вне расписания» «сегодня» заморожено.

- [x] Генеральная: ответ каждой из 8 операций валиден против JSON Schema openapi.json
      (включая POST с телом и статусы 400/404/409). —
- [x] Создание типа встреч: 201, форма `AdminMeetingTypeCreated`. — С1
- [x] Создание брони: 201; `end` вычислен сервером; `start` в ответе со смещением `+03:00`;
      `meetingTypeName` денормализован. — С2
- [x] 400 `validation_failed`: `name`/`guestName` вне 1–100 символов или из одних пробелов;
      `durationMinutes` вне 5–540. — С1, С2
- [x] 404 `meeting_type_not_found`: неизвестный id в получении типа, слотах и брони. — С2
- [x] 409 `slot_taken`: повторная бронь занятого слота и частичное наложение интервалов разных
      типов (конец брони может не совпадать с сеткой запрашиваемого типа). — С2
- [x] 409 `outside_window` / `outside_schedule`: старт вне окна записи или расписания. — С2

## Юнит (модели)

Vitest над инвариантами сущностей и доменными ошибками (ADR 0004); тексты не пиннятся —
проверяется вид `DomainError`.

- [x] Тип встречи: имя 1–100 символов без пробелов по краям, описание 0–1000, длительность —
      целое 5–540; нарушение → `DomainError('invalid_value')`. — С1
- [x] Бронирование: `guestName` — 1–100 символов без пробелов по краям; `draftBooking`
      переносит денормализованное имя типа и считает `endMs` из длительности типа
      (граничные длительности); нарушение → `DomainError('invalid_value')`. — С2
- [x] Правила брони (`assertSlotBookable`): окно D+1…D+14 из расписания, будни Mon–Fri, сетка
      от начала дня с шагом длительности, конец дня, строгое непересечение; стык разрешён;
      нарушение → `DomainError` нужного вида, приоритет окно → выходной → сетка → конец дня →
      занятость. — С2
- [x] Генератор слотов (`generateSlots`): окно D+1…D+14 по локальной дате, сегодня исключён;
      выходные входят в окно, но слотов не дают; сетка от начала дня с шагом длительности,
      хвост дня отброшен; дни без слотов опущены; строгое непересечение с бронями любого типа,
      стык разрешён; границы длительности 5 и 540 минут. — С2

## Юнит (репозитории)

Vitest над портом на PGlite (ADR 0011): тот же pg-адаптер, что в проде, без моков.

- [x] `create` выдаёт непустой уникальный id; `findById` находит запись и отдаёт `null` на
      промахе; `list()` отдаёт копию в порядке вставки. —
- [x] Порт броней: `create` выдаёт непустой уникальный id и сохраняет запись; `list()` отдаёт
      копию в порядке вставки, а не по времени начала. —

## Юнит (сценарии)

Vitest над сценариями без Fastify (ADR 0004): зависимости приходят явными объектами.

- [x] `getMeetingType`: известный id → сущность, неизвестный → `DomainError('not_found')`
      (404 `meeting_type_not_found` в контракте). — С2
- [x] `createBooking`: создаёт бронь с `endMs` и денормализованным именем типа; неизвестный
      тип → `not_found` раньше правил слота; после ошибки правила ничего не записано;
      пересечение проверяется по броням всех типов. — С2
- [x] `listUpcomingBookings`: `endMs > nowMs` (идущая бронь видна, законченная — нет);
      сортировка по `startMs` независимо от порядка вставки; пустой список. — С3
- [x] `listSlots`: неизвестный тип → `DomainError('not_found')`; `busy` собирается из броней
      всех типов, поэтому чужая бронь сдвигает первый слот дня. — С2

## Юнит (адаптер: момент)

Vitest над форматированием момента (ADR 0004): домен остаётся в epoch-ms, `+03:00` собирает
адаптер по смещению из расписания.

- [x] `formatMoment`: момент в `+03:00` по расписанию по умолчанию; отрицательное смещение
      (`-05:00`); переход через полночь по локальной дате; секунды отбрасываются до `:00`. —

## e2e (Playwright)

Оба вьюпорта (mobile 360×800, desktop 1280×720) гоняют все сценарные спеки; всё через UI,
без API-фикстур.

- [x] Мастер гостя: тип → календарь (дни без слотов дизейбллены) → слоты выбранного дня →
      имя → успех. — С2
- [x] Владелец создаёт тип встреч в Modal. — С1
- [x] Бронь гостя видна во вкладке «Бронирования». — С3
- [x] Отрицательный: ошибка валидации формы гостя видна в UI. — С2
- [x] mobile-view и not-found — существуют, остаются как есть. —

## Покрывается типами (тесты не пишем)

Ловится тремя проходами tsc и `gen:check` статически; типы ловят форму, не поведение —
бизнес-правила сюда не входят, для них есть слои выше.

- Соответствие сервера и клиента типам сгенерированного SDK по каждой операции.
- Zod-схемы форм из `@app/api/zod`.
- Типизация React Query (`@app/api/react-query`).

## Гейты CI

`gen:check` (перегенерация + `git diff --exit-code` по `packages/api/generated`) и контрактный
тест входят в `mise run check`: расхождение артефактов с контрактом или сервера с контрактом
роняет проверку.

`easement check` в том же прогоне держит границы серверных слоёв: `server (wiring) →
server-routes → server-services → server-repositories → server-models`, `server-shared →
server-models`, `api` разрешён всем слоям; `client` и `server` остаются сиблингами. Нарушение
чинится переносом кода или разворотом зависимости, а не правкой `easement.yml`.
