## Стек

- **Node.js 26** — среда выполнения
- **TypeScript 7** — строгая типизация
- **Fastify 5** — HTTP-сервер и API
- **TypeSpec** — описание API-контракта, из него генерируются OpenAPI и SDK
- **React 19** — клиентское приложение
- **Vite 8** — сборка клиента и dev-сервер
- **@fastify/vite** — интеграция Vite с Fastify
- **pnpm 12** — пакетный менеджер

## Установка

В проекте используется [mise](https://mise.jdx.dev/), рекомендуется его установить для простого удобного запуска команд

```bash
git clone https://github.com/kitXIII/ai-for-developers-project-386.git
cd ai-for-developers-project-386

# Установка окружения проекта (Node.js, pnpm и др.)
mise install

# Установка зависимостей, инструментов и git-хуков
mise run setup

# Запуск dev-сервера
mise run
```

## Использование

### Сценарий владельца встречи - создание категории бронирования

На главной странице выбрать "Администрирование" и перейти в интерфейс администратора
Выбрать "виды встреч" (категории бронирования) и перейти на страницу категорий бронирования
Выбрать "cоздать", в диалоговом окне ввести название, описание и длительность категории бронирования
После создания категории бронирования - автоматический переход на страницу категории
На странице созданной категории админ проверяет данные категории и может перейти по ссылке, чтобы убедиться в доступности страницы бронирования для созданной категории

### Сценарий участника встречи - создание бронирования

На главной странице выбрать "Записаться"
Выбрать категорию бронирования из списка и перейти по ссылке
На странице создания бронирования выбрать дату и доступный временной слот, заполнить поле имя и подтвердить бронирование
Пройти на страницу бронирования категории и убедиться, что выбранное время занято

### Сценарий владельца встречи - проверка бронирования

На главной странице выбрать "Администрирование" и перейти в интерфейс администратора
В списке бронирований найти созданное в сценарии участника встречи, проверить совпадение имени и времени

## API-контракт

Контракт API описывается в [TypeSpec](https://typespec.io/) и живёт в workspace-пакете `packages/api` (`@app/api`):

- `packages/api/spec/*.tsp` — источник правды: модели и операции API;
- `packages/api/generated/openapi.json` — OpenAPI 3.1, сгенерированный из TypeSpec;
- `packages/api/generated/client/` — типизированный SDK, типы и Zod-схемы ([hey-api](https://heyapi.dev/)), сгенерированные из OpenAPI.

Сгенерированные артефакты коммитятся. После изменения контракта:

```bash
pnpm gen   # = tsp compile + openapi-ts, во всех workspace-пакетах
```

Как использовать сгенерированное:

- **клиент** импортирует SDK-функции и Zod-схемы: `import { getMessage } from '@app/api'`, `import { zMessage } from '@app/api/zod'`;
- **сервер** импортирует только типы: `import type { Message } from '@app/api/types'` — тип-импорт стирается при компиляции, поэтому рантайм-зависимости сервера от пакета нет.

Расхождение сервера с контрактом ловится двумя механизмами: `tsc` проверяет типы хендлеров против сгенерированных типов, а контрактный тест (`test/api/contract.test.ts`) валидирует ответы живого сервера по JSON Schema из `openapi.json`. CI дополнительно перегенерирует контракт (`mise run gen:check`) и падает, если закоммиченные артефакты устарели.

## Проверки качества

Все проверки запускаются одной командой:

```bash
mise run check
```

Безопасные автоисправления (форматирование, линт, опечатки):

```bash
mise run fix
```

При запуске `mise run setup` производится установка зависимостей, инструментов и git-хуков.
Pre-commit проверяет staged-файлы, pre-push — весь проект, а `.github/workflows/quality.yml` запускает `mise run check` на PR и push в `main`.

Состав проверок задаётся в `mise.toml`; инструмент хуков `hk` (см. `hk.pkl`) только вызывает нужные mise-задачи.

- **oxlint** — линтер TS/TSX: ошибки и подозрительные конструкции, например `debugger` или неиспользуемые переменные.
- **oxfmt** — форматтер кода, конфигов и Markdown: проверяет единый стиль, `mise run fix` переформатирует файлы.
- **tsc** — компилятор TypeScript в режиме `strict` с `noEmit`: проверяет типы, неиспользуемые локальные переменные и параметры.
- **Vitest** — тесты API: запускает файлы `*.test.ts` из каталога `test/`, включая контрактный тест, сверяющий сервер с `packages/api/generated/openapi.json`.
- **knip** — находит мёртвый код: неиспользуемые файлы, экспорты и зависимости.
- **jactionlint** — линтер GitHub Actions и Dependabot: unpinned actions, отсутствие `permissions`, `concurrency` и `timeout-minutes`.
- **typos** — ищет опечатки в коде, конфигах и документации.
- **betterleaks** — сканер секретов: staged-файлы и рабочее дерево, а в недельном CI — всю историю коммитов.
- **OSV-Scanner** — сверяет `pnpm-lock.yaml` с базой уязвимостей OSV и сообщает об известных уязвимостях в зависимостях.
- **agnix** — валидирует конфиги AI-агентов (`AGENTS.md` и подобные): битые ссылки, структуру и согласованность инструкций.

## Тесты

Тесты API написаны на [Vitest](https://vitest.dev/). Они работают через `app.inject()` Fastify, поэтому не поднимают HTTP-сервер и Vite.

```bash
mise run test      # однократный прогон
pnpm test:watch    # режим наблюдения
```

Тесты лежат в каталоге `test/` в файлах `*.test.ts` и входят в `mise run check`. Там же позже появятся тесты клиента (`test/client/`) и e2e.
